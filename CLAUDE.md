# Working in this repo

- Read `docs/GUARDRAILS.md` first and follow it; it lists what must not be done (no compiler forks, no custom renderer, pinned git deps, license checks, keep primitive markup intact, reduced motion, gallery coverage). Its "Parallel sessions" section says how to start, sync and hand over a branch; `docs/notes/` holds newer platform notes.
- Other sessions work in parallel; follow `docs/PROTOCOL.md`. In short: branch from the latest `origin/main`, put changelog entries in `changes/<topic>.md` (never `CHANGELOG.md` or `docs/MIGRATION.md`), run `scripts/sync-main.sh` before every push (it also pulls merges the sync bot pushed to your branch), never rebase or force-push an open PR, and when the sync bot comments on or pushes to your PR, sync and push right away.
- Before pushing run `scripts/check.sh` (add `--a11y` for UI changes); it runs: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace --exclude native` then `cargo test -p native` (headless Blitz), `cargo build -p gallery --target wasm32-unknown-unknown`.
- Every copied file gets a row in `THIRD_PARTY.md`.
- New components: start with `cargo run -p atoll-cli -- new <name>`. It adds the folder in `crates/ui/src/components/`, a demo in `crates/ui/src/demos/<name>.rs`, a test file in `crates/ui/tests/components/<name>.rs` and a gallery section in `apps/gallery/src/main.rs`. The module list, the prelude, `ui::demos::ALL` (smoke, ARIA and snapshot tests walk it) and the test list are generated by `crates/ui/build.rs`; don't add lines for them by hand.
- To run, click through or screenshot an app (gallery, docs, site, dashboard, booking, showcase), use the `run-atoll` skill: `.claude/skills/run-atoll/SKILL.md`.
