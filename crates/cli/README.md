# rust-ui-cli

Copy-paste CLI for the [Rust UI kit](https://github.com/Amit-1of1/Rust-UI-): it copies components (and the components they depend on) into your Dioxus project, shadcn style.

```sh
cargo install --git https://github.com/Amit-1of1/Rust-UI- rust-ui-cli   # installs `rust-ui`
rust-ui --source https://github.com/Amit-1of1/Rust-UI- list
rust-ui --source https://github.com/Amit-1of1/Rust-UI- init --dest assets/theme.css
rust-ui --source https://github.com/Amit-1of1/Rust-UI- add command --dest src/components
rust-ui --source https://github.com/Amit-1of1/Rust-UI- diff command --dest src/components
rust-ui update --dry-run   # later: what moving to the registry's current version would change
rust-ui update             # apply it, merging your edits (three-way, with conflict markers)
rust-ui explain            # cargo check, with kit errors explained in plain words
```

`rust-ui new <snake_case_name>` (inside this repo only) scaffolds a component: folder, demo, test file, gallery section and `registry.json` (the module, prelude and test lists are generated by `crates/ui/build.rs`). `rust-ui changelog` folds the fragments in `changes/` into the changelog before a release.

`rust-ui postbuild <public dir>` shrinks a `dx build --release --platform web` output in place: it drops the wasm's debug names (which `--wasm-split` builds keep) and bundles the theme and the component stylesheets the app uses into one file linked from `index.html`. The app must render `ui::ThemeStyles` (or call `ui::css_bundle::install()`) so components stop linking their own files. `scripts/release-web.sh <app>` runs both steps.

`rust-ui explain [-- <cargo check args>]` runs `cargo check` and rewrites the errors that come from kit components into what to change: "`Dialog` needs the `title` prop" with that prop's documentation, instead of rustc's "this method takes 1 argument but 0 arguments were supplied"; the real props when one is misspelt; the variants of an enum, and the changelog line when one was removed; the line inside an `rsx!` block where a string was given for an enum; and `rust-ui add <name>` for a component that is not copied yet. It reads your copies in `src/components` first. `--json` prints the same for editors and agents; `--from <file>` reads saved `--message-format=json` output. [docs/EXPLAIN.md](../../docs/EXPLAIN.md) has examples.

`rust-ui mcp` is a Model Context Protocol server (stdio) for AI coding tools: they can list, search and read components and add them to the project. Client setup is in [docs/MCP.md](../../docs/MCP.md).

`rust-ui info` (`--json` for agents) describes the app: Dioxus version, theme, installed items and which of them you edited. `rust-ui skill` installs the kit's agent skill into `.claude/skills/rust-ui/`; see [docs/MCP.md](../../docs/MCP.md#agent-skill-and-rust-ui-info).

`--source` is a local checkout or a git URL (shallow-cloned into `~/.cache/rust-ui` and fast-forwarded on later runs; needs `git` on PATH). Set `RUST_UI_SOURCE` to avoid repeating it. `add` keeps files you have edited unless you pass `--force`, and prints the `pub mod` lines for your `components/mod.rs`. It also records what it copied in `rust-ui-lock.json` and `.rust-ui/base/` (commit both), which `update` merges against; see [docs/INSTALL.md](../../docs/INSTALL.md#updating-copied-components).

The components themselves are not on crates.io: they depend on a git-pinned `dioxus-primitives`, which crates.io cannot host. That is why this tool copies source instead.
