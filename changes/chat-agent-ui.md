### Added

- **ui:** Chat and agent UI set (experimental). `ChatLog` follows new messages while the reader is at the end, stops when they scroll up and offers "Jump to latest" / "New messages below" (measured, so it also works on Blitz, which sends no scroll events); `ChatMessage` is an `article` named by its required `author`; `StreamingText` shows a caret while a reply streams; `TypingIndicator`; `ChatComposer` grows with the text, sends on Enter (never on an IME Enter), adds a line on Shift+Enter and turns Send into Stop while `busy`; `ToolCall` shows a tool call's status in words with collapsible details and approval actions; `AgentSteps`/`AgentStep` show a plan. Screen readers hear each streamed reply once, whole, through the log's own announcer (`use_chat_announcer`) instead of every fragment. `label` on `ChatLog`, `author` on `ChatMessage` and `label` on `ChatComposer` are required, so leaving them out fails to compile. Contracts for all three components, browser checks in `tests/e2e/chat.mjs` and Blitz checks in `apps/native/tests/chat.rs`. (#54)
- **ui:** `UiStrings` gains the chat and tool call strings (`jump_to_latest`, `new_messages`, `typing`, `message_from`, `composer_hint`, `send`, `stop`, `tool_*`). (#54)
