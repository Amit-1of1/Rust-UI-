# Rust UI kit

A personal, shadcn-inspired component kit for [Dioxus](https://dioxuslabs.com), with Motion-style animation planned. It borrows instead of inventing: behaviour and accessibility come from [`dioxus-primitives`](https://github.com/DioxusLabs/components), and the styled layer started as a copy of DioxusLabs' components that this repo now owns.

**Read [docs/GUARDRAILS.md](docs/GUARDRAILS.md) before changing anything.**

## Layout

| Path | What |
|---|---|
| `crates/ui` | The kit (`use ui::prelude::*;`). One folder per component: `component.rs`, `style.css`, `docs.md`. |
| `crates/ui/assets/theme.css` | Color tokens for light and dark, plus the reduced-motion rule. |
| `crates/motion` | Motion layer: spring presets, `Pop` enter/exit, `use_spring`, `use_reduced_motion`. The only place that touches the animation engine. |
| `apps/gallery` | Live gallery of every component. A component not shown here isn't done. |
| `apps/docs` | Docs site: one page per component (live demo + `docs.md`) plus the install and theming guides. Its page list is generated by `rust-ui registry`. |

## Run the docs site

```sh
cd apps/docs && dx serve     # http://localhost:8080
```

## Run the gallery

```sh
cargo install dioxus-cli --version 0.7.10 --locked   # once
cd apps/gallery
dx serve                     # web, http://localhost:8080
dx serve --platform desktop --no-default-features --features desktop
```

## Checks (run before every push; CI runs the same)

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build -p gallery --target wasm32-unknown-unknown
```

## Use it in an app

```toml
[dependencies]
dioxus = { version = "0.7.10", features = ["web"] }
ui = { git = "https://github.com/Amit-1of1/Rust-UI-", package = "rust-ui-kit", features = ["web"] }
```

```rust
use dioxus::prelude::*;
use ui::prelude::*;

fn App() -> Element {
    rsx! {
        ThemeStyles {}
        Button { variant: ButtonVariant::Outline, "Hello" }
    }
}
```

## Demo site

`apps/site` ("Orbit") is a small landing page built only from the kit: nav, theme switch, pricing tabs, chart, table, FAQ accordion, command palette, a validated signup form with toast and dialog, a swipe-dismiss banner and an animated waitlist. It is a real-world test of the kit; run it with `dx serve --platform web` in `apps/site`.

## Registry and CLI

`registry.json` lists every component with its files and the other components it needs. It is generated from the folders (`cargo run -p rust-ui-cli -- registry`), and a test fails if it goes stale.

```sh
cargo install --path crates/cli          # installs `rust-ui`
rust-ui --source https://github.com/Amit-1of1/Rust-UI- list
rust-ui init  --dest assets/theme.css
rust-ui add command --dest src/components   # also copies dialog, button, kbd
rust-ui diff command --dest src/components  # exit 1 if your copy differs
```

`add` never overwrites a file you changed unless you pass `--force`. It prints the `pub mod` lines to paste into your `components/mod.rs`. `--source` (or `RUST_UI_SOURCE`) is a local checkout or a git URL such as `https://github.com/Amit-1of1/Rust-UI-`; a URL is shallow-cloned into `~/.cache/rust-ui` and needs `git`.

### Adding a component

`cargo run -p rust-ui-cli -- new status_dot` (run from the repo root) creates the component folder (`component.rs`, `style.css`, `docs.md`, a `Demo`), adds the `pub mod` and prelude lines in sorted order, appends the demo smoke test and render test, adds a gallery section and regenerates `registry.json`. Then fill in the TODOs, add a `THIRD_PARTY.md` row if you copied anything, and run `scripts/check.sh`.

## Gate

`scripts/check.sh` runs fmt, clippy `-D warnings`, the tests, the wasm32 builds (gallery and site) and the registry check. `scripts/check.sh --a11y` also builds the gallery and site with `dx`, serves them and runs axe in light and dark (needs `dx` and `npm ci` in `tests/e2e`).

## Gallery online

`.github/workflows/pages.yml` builds the gallery and deploys it to GitHub Pages (run it manually from the Actions tab after enabling Pages with the GitHub Actions source). Locally: `dx bundle --platform web --release --base-path Rust-UI-` in `apps/gallery`.

## Native (experimental)

`cargo check -p gallery --no-default-features --features native` compiles against Blitz. It has not been run; see `docs/GUARDRAILS.md`.

## Accessibility check

`tests/e2e/axe.mjs` runs axe-core (WCAG 2 A/AA plus best practices) on the built gallery in light and dark. See the header of that file for how to run it. It is not in CI yet because CI cannot currently run (see below).

## Motion

```rust
use ui::motion::{AnimatePresence, Pop, SpringPreset, use_spring};

// Springs: retargeting mid-flight keeps momentum; reduced motion makes it instant.
let mut x = use_spring(0.0, SpringPreset::Snappy);
x.to(120.0);

// Presence: children finish their exit before unmounting. Give each a unique key.
rsx! {
    AnimatePresence {
        for id in items() {
            Pop { key: "{id}", "Item {id}" }
        }
    }
}
```

`FlipList`/`FlipItem` make siblings slide into the gap when a row is removed or added. `SwipeDismiss` is a drag-sideways-to-dismiss wrapper (pointer capture on web, release speed carried into the spring) with a keyboard fallback; its decision logic (`SwipeTracker`) is unit tested.

Baseline open/close animation of the overlay components stays in CSS; springs are for things CSS can't do (interruptible motion, exits driven by state).
