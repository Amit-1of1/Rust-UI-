# atoll-cli

Copy-paste CLI for the [Atoll kit](https://github.com/Amit-1of1/Rust-UI-): it copies components (and the components they depend on) into your Dioxus project, shadcn style.

```sh
cargo install --git https://github.com/Amit-1of1/Rust-UI- --branch main atoll-cli   # installs `atoll`
atoll --source https://github.com/Amit-1of1/Rust-UI- list
atoll --source https://github.com/Amit-1of1/Rust-UI- init --dest assets/theme.css
atoll --source https://github.com/Amit-1of1/Rust-UI- add command --dest src/components
atoll --source https://github.com/Amit-1of1/Rust-UI- diff command --dest src/components
atoll update --dry-run   # later: what moving to the registry's current version would change
atoll update             # apply it, merging your edits (three-way, with conflict markers)
atoll explain            # cargo check, with kit errors explained in plain words
```

`atoll new <snake_case_name>` (inside this repo only) scaffolds a component: folder, demo, test file, gallery section and `registry.json` (the module, prelude and test lists are generated by `crates/ui/build.rs`). `atoll changelog` folds the fragments in `changes/` into the changelog before a release.

`atoll postbuild <public dir>` shrinks a `dx build --release --platform web` output in place: it drops the wasm's debug names (which `--wasm-split` builds keep) and bundles the theme and the component stylesheets the app uses into one file linked from `index.html`. The app must render `ui::ThemeStyles` (or call `ui::css_bundle::install()`) so components stop linking their own files. `scripts/release-web.sh <app>` runs both steps.

`atoll explain [-- <cargo check args>]` runs `cargo check` and rewrites the errors that come from kit components into what to change: "`Dialog` needs the `title` prop" with that prop's documentation, instead of rustc's "this method takes 1 argument but 0 arguments were supplied"; the real props when one is misspelt; the variants of an enum, and the changelog line when one was removed; the line inside an `rsx!` block where a string was given for an enum; and `atoll add <name>` for a component that is not copied yet. It reads your copies in `src/components` first. `--json` prints the same for editors and agents; `--from <file>` reads saved `--message-format=json` output. [docs/EXPLAIN.md](../../docs/EXPLAIN.md) has examples.

`atoll mcp` is a Model Context Protocol server (stdio) for AI coding tools: they can list, search and read components and add them to the project. Client setup is in [docs/MCP.md](../../docs/MCP.md).

`atoll info` (`--json` for agents) describes the app: Dioxus version, theme, installed items and which of them you edited. `atoll skill` installs the kit's agent skill into `.claude/skills/atoll/`; see [docs/MCP.md](../../docs/MCP.md#agent-skill-and-atoll-info).

`atoll acr [names] --product <name> --out acr.md` writes a draft Accessibility Conformance Report (the VPAT 2.5 WCAG 2.2 layout) for the components your app uses (the lockfile's items by default), from the kit's tests and keyboard contracts, with every row the app must still check marked *review*. See [docs/ACR.md](../../docs/ACR.md).

`--source` is a local checkout or a git URL (shallow-cloned into `~/.cache/atoll` and fast-forwarded on later runs; needs `git` on PATH). Set `ATOLL_SOURCE` to avoid repeating it. `add` keeps files you have edited unless you pass `--force`, and prints the `pub mod` lines for your `components/mod.rs`. It also records what it copied in `atoll-lock.json` and `.atoll/base/` (commit both), which `update` merges against; see [docs/INSTALL.md](../../docs/INSTALL.md#updating-copied-components).

The components themselves are not on crates.io: they depend on a git-pinned `dioxus-primitives`, which crates.io cannot host. That is why this tool copies source instead.
